# Custom Canvas UI

[Custom Canvas](/self-serve/custom-canvas/introduction) is a feature that lets your users build their own dashboards inside your product. This page covers **styling** and **translating** its interface; see also [Deploying Custom Canvas](/deployment/custom-canvas).

The UI components powering Custom Canvas (panels, forms, buttons, cards) are built on [Remarkable UI](https://github.com/embeddable-hq/remarkable-ui). These components are _currently_ fixed - you can't swap them out or modify their behavior - but you can **style them** to match your brand using CSS variables.

## How to Style Custom Canvas

Add variables to `theme.styles` in your theme:

```ts
// embeddable.theme.ts
const themeProvider = (clientContext: any, parentTheme: Theme): Theme => {
  return defineTheme(parentTheme, {
    styles: {
      "--em-sem-background": "#f8f9fa",
      "--em-sem-text": "#1a1a2e",
    },
  });
};
```

For full theming details, see [Theming Remarkable Pro](/component-libraries/remarkable-pro/theming) and [How Styling Works](/component-libraries/remarkable-pro/styling/introduction).

## Translating the Interface

Custom Canvas ships its labels in English - "Add a chart", "Select a template", validation messages, and so on. The drill-down modal does the same. You can replace any of them from your theme, under `theme.embeddableApp.i18n`.

This is separate from [Remarkable Pro's internationalization](/component-libraries/remarkable-pro/i18n), which lives under `theme.i18n` and covers your components. `theme.embeddableApp` belongs to the platform itself, so it works the same way whether or not you use Remarkable Pro.

### How to translate

```ts
// embeddable.theme.ts
const themeProvider = (clientContext: any, parentTheme: Theme) => {
  return defineTheme(parentTheme, {
    embeddableApp: {
      i18n: {
        language: clientContext?.language || "en",
        translations: {
          de: {
            customCanvas: {
              addChart: "Diagramm hinzufügen",
              templateSelection: {
                title: "Vorlage auswählen",
                populateTitle: "{{templateName}} ausfüllen",
              },
              validation: {
                valueRequired: "Wert ist erforderlich",
              },
            },
            drillDown: {
              step: "Schritt {{number}}",
            },
          },
        },
      },
    },
  });
};
```

**Things to notice**

1. `embeddableApp.i18n.language` selects the active catalogue, and defaults to `en`. The platform reserves no [Client Context](/component-libraries/client-context) fields of its own, so map your own locale field onto it, as above.
2. Translate only the keys you need. Anything you leave out falls back to the built-in English, so a partial catalogue is a valid catalogue.
3. `{{...}}` are placeholders, filled in when the label is rendered. You can move them: `Populate {{templateName}}` becomes `{{templateName}} ausfüllen` in German. Never assemble a label by joining pieces together - word order differs between languages.
4. Each `<em-beddable>` resolves its own labels, so several embeddables on one page can run different languages.

To try it in the Builder, add presets to your `client-contexts.cc.yml`:

```yaml
# src/embeddable.com/presets/client-contexts.cc.yml

- name: German
  clientContext:
    language: de

- name: Spanish
  clientContext:
    language: es
```

Switching between them swaps the language of the whole interface:

### Changing the English wording

The built-in English is a catalogue like any other. If you only want the interface to match your product's terminology, override it without translating anything:

```ts
embeddableApp: {
  i18n: {
    language: "en",
    translations: {
      en: {
        customCanvas: { addChart: "Add a widget" },
      },
    },
  },
},
```

Your `en` catalogue also acts as the base for every other language. A label you reword there shows up in German too, unless your `de` catalogue gives it its own value - so terminology changes only need writing once.

Labels resolve in this order:

1. the catalogue for `language`
2. your `en` catalogue
3. the built-in English

### What isn't translated here

1. **Template names and descriptions** are authored in the [Builder](/self-serve/custom-canvas/building-it) and are shown exactly as written there.
2. **Your components' own labels** - titles, axis labels, column headers and data values - belong to your component library. On Remarkable Pro, translate them under [`theme.i18n`](/component-libraries/remarkable-pro/i18n).

### Type safety

`@embeddable.com/core` exports the types for this namespace, so your editor autocompletes the keys and a mistyped key fails the build rather than silently rendering English:

```ts
// embeddable.theme.ts
import { defineTheme, EmbeddableTheme } from "@embeddable.com/core";
import { Theme } from "@embeddable.com/remarkable-pro";

type AppTheme = Theme & EmbeddableTheme;

const themeProvider = (clientContext: any, parentTheme: Theme): AppTheme =>
  defineTheme<AppTheme>(parentTheme, {
    embeddableApp: { i18n: { /* ... */ } },
  });

export default themeProvider;
```

Requires `@embeddable.com/core` 2.15.0 or later.

### Custom Canvas Overlay

The overlay is the modal that hosts the [template selector and the chart configurator](/self-serve/custom-canvas/end-user-experience). Its variables sit in their own `--em-canvas-overlay-*` namespace, so overriding them doesn't affect the rest of your dashboard.

#### Coverage and box

| Variable                            | Description                                         | Default          |
| ----------------------------------- | --------------------------------------------------- | ---------------- |
| `--em-canvas-overlay-position`      | `fixed` (viewport) or `absolute` (parent container) | `fixed`          |
| `--em-canvas-overlay-inset`         | Inset for the modal and the dim                     | `0`              |
| `--em-canvas-overlay-max-width`     | Maximum content width                               | `78rem`          |
| `--em-canvas-overlay-padding`       | Inner spacing of the content area                   | `0 2rem 2.25rem` |
| `--em-canvas-overlay-border-radius` | Corner rounding of the content area                 | `1.75rem`        |

- `--em-canvas-overlay-position` accepts `fixed` (default - the modal and the dim cover the viewport) or `absolute` (they cover only the embeddable's region). When using `absolute`, the embeddable's parent must be a positioned ancestor, e.g. `position: relative`.
- `--em-canvas-overlay-inset` accepts any CSS `inset` shorthand (`5rem`, `1rem 2rem`, `1rem 2rem 3rem 4rem`) and insets the modal **and** the dim layer together.

#### Colors

| Variable                                       | Description                | Default                                      |
| ---------------------------------------------- | -------------------------- | -------------------------------------------- |
| `--em-canvas-overlay-backdrop-background`      | Dim layer behind the modal | `var(--em-overlay-background)`               |
| `--em-canvas-overlay-content-background`       | Content panel fill         | `transparent`                                |
| `--em-canvas-overlay-title-color`              | Overlay title color        | `var(--em-sem-text--inverted)`               |
| `--em-canvas-overlay-action-button-background` | Back / close button fill   | `var(--em-buttonicon-background--secondary)` |
| `--em-canvas-overlay-action-button-color`      | Back / close icon color    | `var(--em-buttonicon-color--secondary)`      |

- the background is split in two: `--em-canvas-overlay-backdrop-background` is the dim behind the modal, `--em-canvas-overlay-content-background` is the panel holding the topbar, template grid and configurator. The content panel defaults to `transparent`, which is why cards appear to float over the dim.
- the action-button variables only apply to the overlay's back and close buttons - other icon buttons keep their own styling.

#### Configurator actions bar

| Variable                                      | Description                                                                            | Default  |
| --------------------------------------------- | -------------------------------------------------------------------------------------- | -------- |
| `--em-canvas-overlay-actions-justify-content` | Horizontal position of the cancel / confirm pill: `flex-start`, `center` or `flex-end` | `center` |
| `--em-canvas-overlay-actions-position`        | `sticky` floats the pill while scrolling, `static` lets it scroll with the content     | `sticky` |

For the complete set, see [Canvas Overlay](#canvas-overlay) in the full variable reference below.

## Tips

- **Override sparingly**: Change only what's needed to match your brand. Fewer overrides means easier maintenance.
- **Test both themes**: If you support light and dark modes, verify your changes work in both contexts.
- **Check accessibility**: Ensure sufficient color contrast between text and backgrounds.
